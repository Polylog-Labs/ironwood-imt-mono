ABOUT THIS EXPLORER

Where the data comes from

The Rust indexer reads public Zcash chain data from lightwalletd servers. The public provider pool includes Stardust, Cake Wallet, Zec.rocks, and ZcashESP, with automatic failover when a provider is unavailable. The provider status ↗ shows which sources are currently selected.

How we build and verify the tree

Starting at Ironwood activation, we append commitments in block, transaction, and action order. We compute the tree with Sinsemilla and compare roots with upstream tree state before saving verified batches in SQLite. The indexer handles chain reorganizations and resumes from its saved checkpoint. It relies on upstream validating nodes for consensus; it is not an independent full node.

What a leaf represents

A leaf is a public note commitment. Spending a note does not remove its commitment. Shielded recipients and note amounts remain private. Select an occupied leaf to see its transaction and zero-based action index. The added time is the containing block's UTC timestamp, not an exact arrival time.

How the view stays live

The browser checks our API every 10 seconds while this tab is visible and loads only the tree region you explore. Mempool values are unconfirmed commitments observed by a provider; they are not yet leaves. Fill dates assume the last 24 hours' absolute growth continues at the same rate.
