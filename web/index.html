How these figures are calculated

Each calendar square counts distinct confirmed transactions involving Ironwood, including transfers across pools. Miner coinbase transactions are excluded. One transaction can add multiple leaves to the tree because each Ironwood action adds a note commitment. The tree also includes actions in miner coinbase transactions. Dates and hours use the block timestamp in UTC. The brightest squares mark the upper quarter of active days in the displayed range.

Pool flows use the signed net Ironwood value of each decoded transaction mined on the selected UTC date. Inflows and outflows have separate medians. The panel shows how much of the day has been indexed for flows. Ironwood-only transactions can pay a miner fee from the pool and are excluded from both groups. A mixed transaction’s net value can include its fee. Amounts paid between shielded users remain private.

Weekday rankings compare median transaction counts per complete UTC day over the indexed year. The average wait for first confirmation uses the time between seeing a pending transaction and indexing its block. The first-to-tenth interval measures how long nine more blocks take after that first block. Both timing figures cover the last seven days. The last complete hour is compared with the same UTC hour on up to 28 preceding days. Shielded block usage measures the share of the NU7 shared action budget consumed by all shielded pools.
